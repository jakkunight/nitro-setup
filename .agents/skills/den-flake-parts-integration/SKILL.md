# Den + flake-parts Integration

Integrate the Den aspect-oriented Nix configuration framework with flake-parts for modular, feature-first NixOS/Darwin/Home-Manager configurations.

## Overview

Den integrates seamlessly with flake-parts through `den.flakeModule`, providing a powerful combination for modular Nix configuration. This skill covers the actual entry point for integrating Den into a working Nix flake — the most common starting point for Den users.

**Prerequisite**: Understand Den's four concerns (Entity, Aspect, Policy, Quirk). See `den-core-concepts` for the mental model.

---

## Adding Den to a flake-parts Flake

### Step 1: Add Inputs

```nix
{
  inputs = {
    nixpkgs.url = "github:nixos/nixpkgs/nixos-25.11";
    flake-parts.url = "github:hercules-ci/flake-parts";
    den.url = "github:denful/den";
    import-tree.url = "github:denful/import-tree";
  };
  outputs = inputs: inputs.flake-parts.lib.mkFlake {
    inherit inputs;
  } (inputs.import-tree ./modules);
}
```

### Step 2: Import `den.flakeModule`

```nix
# modules/den.nix
{ inputs, ... }: {
  imports = [ inputs.den.flakeModule ];
}
```

### Step 3: Declare Hosts and Users

```nix
# modules/hosts.nix
{ den, ... }: {
  den.hosts.x86_64-linux.laptop.users.alice = {};
  den.hosts.aarch64-darwin.mac.users.bob = {};
}
```

### Step 4: Set Global Defaults

```nix
# modules/defaults.nix
{ den, lib, ... }: {
  den.default.nixos.system.stateVersion = "25.11";
  den.default.homeManager.home.stateVersion = "25.11";
  den.schema.user.classes = lib.mkDefault [ "homeManager" ];
  den.default.includes = [ den.batteries.define-user ];
}
```

## den.flakeModule

The main flake module that:
- Provides the `den` module argument
- Registers all `den.*` options
- Sets up flake output generation

```nix
{ inputs, ... }: {
  imports = [ inputs.den.flakeModule ];
}
```

## den.flakeOutputs Modules

Handle flake output generation for NixOS, Darwin, and Home-Manager configurations.

### Available Output Modules

| Module | Description |
|--------|-------------|
| `nixosConfigurations` | NixOS host outputs |
| `darwinConfigurations` | Darwin host outputs |
| `homeConfigurations` | Home-manager outputs |
| `packages` | Flake packages |
| `apps` | Flake apps |
| `checks` | Flake checks |
| `tests` | Flake tests |
| `legacyPackages` | Legacy packages |
| `devShells` | Development shells |
| `all` | All outputs |
| `flake` | Full flake output |

### Usage

```nix
# modules/dendritic.nix
{ inputs, den, ... }: {
  imports = [
    inputs.den.flakeOutputs.nixosConfigurations
    inputs.den.flakeOutputs.homeConfigurations
  ];
}
```

## Module Arguments

### den.batteries.inputs'

Provides `inputs'` (flake inputs with system pre-selected) as a top-level module argument:

```nix
den.default.includes = [ den.batteries.inputs' ];

den.aspects.my-aspect = {
  inputs', ... }: {
    # inputs' has system pre-selected
    nixos = { pkgs, ... }: {
      environment.systemPackages = [
        inputs'.my-tool.packages.${pkgs.stdenv.hostPlatform.system}.default
      ];
    };
  };
};
```

### den.batteries.self'

Provides `self'` (flake self outputs with system pre-selected):

```nix
den.default.includes = [ den.batteries.self' ];
```

### den.batteries.flake-scope

Exposes `lib`, `inputs`, and `den` to aspect pipeline functions **and** class modules:

```nix
den.default.includes = [ den.batteries.flake-scope ];

den.aspects.my-aspect = { host, inputs, lib, ... }: {
  nixos = { pkgs, ... }: {
    environment.etc."version".text = inputs.nixpkgs.lib.version;
  };
};
```

Values are tagged `pipelineOnly` (class-wins collision policy).

## Custom Classes into flake-parts Scope

### Creating a Custom flake-parts Class

```nix
# modules/classes/packages.nix
{ den, lib, ... }: let
  fwd = { host, ... }:
    den.batteries.forward {
      each = lib.singleton true;
      fromClass = _: "packages";
      intoClass = _: "flake-parts";
      intoPath  = _: [ "perSystem" "packages" ];
      fromAspect = _: host.aspect;
    };
in {
  den.classes.packages = {
    description = "Packages for perSystem";
  };
  den.schema.host.includes = [ fwd ];
}
```

### Wiring Classes into flake-parts Scope

```nix
# Any module can contribute new perSystem classes
den.schema.flake-parts.includes = [
  (den.batteries.import-tree.provides.host ./classes)
];
```

### The flake-parts-modules Template

The `flake-parts-modules` template demonstrates how to use Den aspects that propagate custom classes into third-party flake-parts `perSystem` modules.

Example features:
- `perSystem.packages` — Expose flake-parts packages
- `numtide/devshell` — Default devshell extensible by any aspect
- `numtide/treefmt-nix` — Shared formatter configured across aspects
- `sini/files` — Generates README from nix code
- `nix-community/nix-unit` — Write tests directly on aspects

## Policy Effects Injecting into flake-parts

Policies can inject configuration into flake-parts scopes:

```nix
let inherit (den.lib) policy;
den.policies.inject-into-flake = { host, ... }:
  [ (policy.provide {
      class = "flake-parts";
      module = { perSystem = { ... }: {
        packages.my-app = ...;
      }; };
    })
  ];
```

### Aspect-Level Policies

Aspects can define policies inline:

```nix
den.aspects.igloo = {
  policies.to-users = { host, user, ... }:
    lib.optional someCondition
      (policy.include { nixos.some.option = true; });
  includes = [ den.aspects.igloo.policies.to-users ];
};
```

## den.schema.flake-parts

Den supports `flake-parts` as an entity kind:

```nix
den.schema.flake-parts = { lib, ... }: {
  options = {
    # Custom options for flake-parts entities
  };
};
```

### Schema Includes

Activate policies for flake-parts:

```nix
den.schema.flake-parts.includes = [
  den.policies.flake-parts-to-system
];
```

## Migration from Traditional flake-parts

### Before: Traditional flake-parts

```nix
{
  outputs = inputs: inputs.flake-parts.lib.mkFlake {
    inherit inputs;
  } {
    systems = [ "x86_64-linux" ];
    perSystem = { pkgs, ... }: {
      nixosConfigurations.laptop = pkgs.lib.nixosSystem {
        modules = [ ./hosts/laptop.nix ];
      };
    };
  };
}
```

### After: Den + flake-parts

```nix
{
  inputs = {
    den.url = "github:denful/den";
    import-tree.url = "github:denful/import-tree";
  };
  outputs = inputs: inputs.flake-parts.lib.mkFlake {
    inherit inputs;
  } (inputs.import-tree ./modules);
}
```

```nix
# modules/den.nix
{ inputs, ... }: {
  imports = [ inputs.den.flakeModule ];
  den.hosts.x86_64-linux.laptop.users.alice = {};
  den.aspects.laptop = {
    nixos = { pkgs, ... }: {
      environment.systemPackages = [ pkgs.git ];
    };
  };
}
```

### Key Differences

| Aspect | Traditional flake-parts | Den + flake-parts |
|--------|------------------------|-------------------|
| Organization | Host-first | Aspect-first |
| Configuration | Per-system modules | Parametric aspects |
| Sharing | Stringly-typed module names | Real aspect references |
| Cross-entity | Manual wiring | Automatic via policies |
| Data flow | Manual options | Quirks + pipes |
| Context | specialArgs | Function parametric dispatch |

## Best Practices

### 1. Use `den.flakeModule`

Always import Den's flake module — it sets up all the infrastructure.

```nix
{ inputs, ... }: {
  imports = [ inputs.den.flakeModule ];
}
```

### 2. Leverage `den.batteries.inputs'`

For flake-parts-style module arguments with system pre-selected.

### 3. Create Custom Classes

For extending flake-parts with Den aspects:

```nix
den.classes.myClass = {
  description = "My custom class";
  forwardTo = { class = "nixos"; path = [ "some" "path" ]; };
};
```

### 4. Use `den.schema.flake-parts`

For flake-parts-specific options.

### 5. Activate Policies

Use `den.schema.flake-parts.includes` to wire policies:

```nix
den.schema.flake-parts.includes = [
  den.policies.flake-parts-to-system
];
```

### 6. Test with `nix flake check`

Use the CI template for testing:

```bash
nix flake init -t github:denful/den#ci
nix flake check -L
```

## Anti-Patterns to Avoid

### 1. Don't Mix Legacy and Den in Same Module

```nix
# Bad
{
  imports = [ inputs.den.flakeModule ];
  networking.hostName = "laptop";  # Legacy NixOS option
  den.hosts.x86_64-linux.laptop = {};
}

# Good
{
  imports = [ inputs.den.flakeModule ];
  den.hosts.x86_64-linux.laptop = {};
  den.aspects.laptop.nixos.networking.hostName = "laptop";
}
```

### 2. Don't Hardcode Host Names

```nix
# Bad
nixos.networking.hostName = "laptop";

# Good
den.aspects.networking = { host, ... }: {
  nixos.networking.hostName = host.name;
};
```

### 3. Don't Use Stringly-Typed Aspect References

```nix
# Bad
includes = [ "dev-tools" "gaming" ];

# Good
includes = [ den.aspects.dev-tools den.aspects.gaming ];
```

## Quick Reference

### den.lib.policy Effects

```nix
let inherit (den.lib) policy;

# Enrich current scope
policy.resolve { myFlag = true; }

# Create child entity scope
policy.resolve.to "user" { inherit host user; }

# Include an aspect
policy.include den.aspects.monitoring

# Provide a module to a class
policy.provide { class = "nixos"; module = { ... }; }

# Route content between scopes
policy.route "homeManager" [ "home-manager" "users" userName ]

# Exclude a policy
policy.exclude den.policies.blocked
```

### den.lib.policy.pipe

```nix
let inherit (den.lib.policy) pipe;

pipe.from "firewall"
pipe.filter (e: e.proto == "tcp")
pipe.transform (b: "${b.addr}:${toString b.port}")
pipe.as "monitoring-targets"
pipe.expose
pipe.collect ({ host, ... }: true)
pipe.broadcast
```

### den.lib.policy Conditional

```nix
den.lib.policy.for den.hosts.x86_64-linux.igloo den.policies.my-policy
den.lib.policy.when ({ host, ... }: host.wsl.enable) den.policies.wsl-support
```

## Key Takeaways

1. **Import `den.flakeModule`** — Sets up all Den infrastructure
2. **Use `den.batteries.inputs'` and `self'`** — For flake-parts-style module arguments
3. **Create custom classes** — For extending flake-parts with Den aspects
4. **Use `den.schema.flake-parts`** — For flake-parts-specific options
5. **Activate policies** — Wire policies through `den.schema.flake-parts.includes`
6. **Feature-first** — Aspects are primary, hosts just select them
7. **Parametric dispatch** — Function args determine activation, no `mkIf`
8. **Zero lock-in** — Works with or without flakes, flake-parts, or home-manager
